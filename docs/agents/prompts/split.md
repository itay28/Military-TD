# Split task prompt

The prompt of the split agent. `.github/workflows/split-issue.yml` runs Claude (Opus) with it when auto-start gives up on an issue: its implement session died twice without finishing, most likely because the work didn't fit one session (`scripts/auto-start.ts` → `giveUpIssue`, #303). The workflow names the issue.

## The task

You split one issue into smaller issues that each fit one agent session, so auto-start can finish the work. Nobody is watching; don't ask questions in a chat. Sign every comment with a blank line and `_Generated by [Claude Code](https://claude.ai/code)_`.

1. **Read the issue and what the dead sessions left:** `gh issue view <n> --json title,body,labels,milestone,comments`. The plan comment and the progress comments say what got done and where it stopped. If a draft PR closes the issue, read its body and `gh pr view <pr> --json headRefName,files` to see what's on its branch; `git log` and `git diff` help with the details. Read only what you need.
2. **Can it be split?** If the work is one indivisible step (an XS or S issue that died for another reason, a bug with no smaller part), don't split it. Comment why, run `gh issue edit <n> --add-label needs-you --remove-label needs-split`, and stop: that hands it to the maintainer.
3. **Plan 2–4 parts**, in the order they can be built, each one shippable on its own with its own tests, and each Size S or M (`docs/agents/issue-tracker.md` → **Project board** → Size). Together they cover the original acceptance criteria, minus anything a dead session already finished on its branch. Don't add scope.
4. **Create each part** with `gh issue create` and the same milestone and `area:*` label as the original, plus `ready-for-agent`, `split-part`, one `size:*` and one `priority:*` label (the original's priority). The body has the part's goal, its slice of the acceptance criteria, `Split from #<n>.`, and, for the first part when a dead session pushed a branch, the line `Continue branch <branch> (draft PR #<pr>).`
5. **Link them.** Find the original's epic: `gh api repos/itay28/Military-TD/issues/<n>/parent --jq .number`. Add each part under it: `gh api -X POST repos/itay28/Military-TD/issues/<epic>/sub_issues -F sub_issue_id=<id>`, where `<id>` comes from `gh api repos/itay28/Military-TD/issues/<part> --jq .id`. Make each part after the first blocked by the one before it: `gh api -X POST repos/itay28/Military-TD/issues/<part>/dependencies/blocked_by -F issue_id=<id of the previous part>`.
6. **Hand over the draft PR** when there is one: change `Closes #<n>` in its body to `Closes #<first part>` (`gh pr edit <pr> --body-file <file>`), so the first part's agent continues it.
7. **Close the original:** comment `Split into #a, #b, #c: <one line on why>.`, then `gh issue edit <n> --remove-label needs-split --remove-label auto-agent` and `gh issue close <n> --reason "not planned"`.

The workflow dispatches *Board sync* afterwards, which copies the labels to the board and can start the first part.
